# Current implementation

This is an as-built snapshot, not a claim of Arcforge parity. **Build checkpoint (2026-11-12):** Four Heat Cell tiers are implemented as automatic heat buffers with source-shaped crafting/loot data. Runtime diagnosis found duplicate `.hmod` and native Rust declarations for the Crushing Array casing and Resin Tap; these duplicates made Horizon reject all Arcforge native item/block declarations. Their states now live in Rust and the duplicate files are removed. CI uses `tools/fetch_mojang_inputs.py` to download Horizon-pinned Minecraft client and Linux library inputs from Mojang and verify each file without publishing them. GitHub run [43339016409](https://github.com/Sipper1236/arcforge-horizon/actions/runs/43339016409) passed preparation but native-build rejected a symlink in the nested Horizon checkout. The workflow now stages the manifest and API into a clean folder. The active completion target is in [goal.md](../goal.md), and the resumable project state is in [handoff.md](../handoff.md). For verification strength, see [verification.md](verification.md). The code targets Arcforge commit `8843cb02cf9132f278f6a8e804b6d78837d3cbcb` and Horizon Nightly 2026-11-08, commit `fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca`.

## Implemented behavior in source

- **Pressurized Conduits:** four tiers route the 22 Arcforge gases listed in the pinned source through separate networks at 400/1,600/6,400/25,600 mB/t, with recipes, tags, and loot. The gas list matches upstream `gas_properties.json`. This source compiles and the content archive passes Horizon's checker; arbitrary third-party gas classification is unsupported by the pinned API, and network behavior is not in-world verified.

- **Heat Cells:** all four tiers are registered with source-derived HU capacities, transfer rates, maximum temperatures, and passive loss rates. Stored HU persists in block-entity data, transfers only downhill through adjacent supported heat connections within the tier's total per-tick rate, and updates the existing five-level heat blockstate. Mining and placement carry charge in custom data. Four source-shaped crafting recipes and explosion-aware loot tables are packaged. The alpha automatically connects all six sides; custom screens, capsule slots, insulation upgrades, redstone controls, side configuration, and charge-preserving tier upgrades are not implemented. No in-world transfer, loss, persistence, or visual check has been run.

- **Item Conduits:** all four source tiers are registered with their Arcforge models, source loot tables, and survival recipes. Connected runs are cached and invalidated on conduit placement, breaking, Wrench changes, or a changed local conduit edge. They use Horizon's transactional item-move helper between configured Output and Input faces. Each network uses its slowest tier: 8/16/32/64 items every 20/10/5/2 ticks. The Wrench changes a face through Auto, Input, Output, and Disabled; Output faces extract from adjacent inventories and Input faces insert into them. A refused transfer stays at its source. Animated packets, conduit-held items, filters, and capability-based Auto detection are absent. Tier upgrades use shaped recipes and do not preserve Wrench face settings. Routes and transfers have not been tested in-world.

- **Metal Press:** upstream recipe selection, die matching, input counts, duration, outputs, and 20 FE/t. Dies are reusable and saved in inventory.
- **Sifter:** four upstream recipes, independent output rolls, mesh tiers, six output slots, and a 20,000 FE buffer.
- **Arc Crusher:** 83 recipe definitions, recipe timing/results/bonus chance/ore-yield handling, and output backpressure. The Crushing Array runs three lanes in a formed 3×3×3 casing cube, with the center casing as controller. Lane priority rotates each tick to prevent starvation when available FE cannot advance all active lanes. Placement and recovery ticks form complete cubes; breaking a casing unforms the remaining parts. Casing FE buffers consolidate into the center before processing. Item access is center-only; facing is north-fixed, ports/upgrades are not implemented, and the older standalone controller id remains available for save compatibility.
- **Machine block drops:** source loot tables are now present for the Arc Crusher, Carbonizer, Fiberizer, Firebox, Induction Furnace, Infuser, Metal Press, Sifter, Steel Block, and Vulcanizer. These preserve upstream explosion-survival conditions and custom-name component copying. An upstream Raw Arcite Block loot table is also now present. Bundle validation for these eleven additions is recorded in `verification.md`.
- **Carbonizer:** four upstream recipes, 8,000 mB saved creosote tank, and item/fluid output checks.
- **Infuser:** the source-shaped survival crafting recipe is now included. It loads ten upstream recipes, five input tags, five treated-wood outputs, 20,000 FE buffer, 8,000 mB creosote tank, 20 FE/t, and custom-bucket exchange.
- **Treated Wood building set:** all 13 upstream log, wood, plank, stair, slab, fence, gate, door, trapdoor, pressure plate, and button blocks are registered. They use nonflammable Crimson-family templates with source hardness, blast resistance, map color, and sound properties; the full nine source crafting recipes, 13 loot tables, and block/item treated-log tags are present. Infusing yields the four treated log/wood forms and treated planks. The pinned Arcforge source defines no treated sign variants; farm/compost progression recipes remain unimplemented.
- **Resin Tap:** a 200-tick timer, log-facing check, upstream 3×3 natural-leaf search through twelve blocks with the two-block trunk-gap cutoff, 25 mB Latex drips from jungle logs into a 1,000 mB tank, 50% Pine Resin chance for spruce logs, 15% for other logs, and a 16-item output cap. The inventory is output-only and a hopper can extract from below. Empty-hand right-click collection uses the pinned API; any resin that does not fit in the player inventory is spawned as a world item. If the loaded chunk or server hook prevents the spawn, the resin is restored to the tap. Empty buckets fill into 1,000 mB Latex Buckets and Latex Buckets empty back into the tap; the bucket's Horizon item-fluid capability is registered. Two Pine Resin and one kelp craft a slime ball, matching the upstream shapeless recipe. Configuration, particles, and custom status tooltip are not implemented.
- **Ore and mineral worldgen:** Silver, Nickel, Fluorite, Bismuth, Tungsten/Wolframite, Arcite, Spodumene, Uraninite, Galena, Halite, Nether Sulfur, End Iolite, Spodumene Pegmatite, and Heavy Mineral Sand use vanilla configured and placed features with source-default sizes, counts, height bands, shapes, and biome selectors. Loot, compatibility/mining tags, and furnace recipes are included where applicable. Arcforge's worldgen toggles/custom serializers are unavailable in the pinned content format. Halite keeps its source rarity, size and Y band but uses a vanilla ore cluster rather than the source's custom flat-bed geometry.
- **Ore reduction recipes:** 32 upstream vanilla smelting and 31 blasting recipes now process the registered Arcforge ores, raw materials, and dusts into their intended crystals, ingots, glass, or vanilla products. The `c:dusts/iron` tag now resolves to Arcforge Iron Dust, completing the source shapeless recipe that combines two Iron Dust and one Nickel Dust into three Invar Dust; Invar Dust can then be crushed and smelted through its existing paths. Common `c:dusts/*` tags, including the local iron, redstone, and sulfur dust tags, support current recipe inputs. Two source smelting recipes remain omitted: flour to bread needs the unregistered Flour item, and yellowcake calcining needs unimplemented uranium intermediates.
- **Combustion Plant:** burns coal, charcoal, coal blocks and their Bio Coal equivalents at twice furnace speed; produces 40 FE/t into a saved 50,000 FE buffer; pauses the burn clock while full; pushes up to 200 FE/t to adjacent Arcforge consumers and exposes the same bounded output through Horizon's energy capability; and has a 50% Wood Ash chance when charcoal finishes burning. The ash goes to a saved output slot with hopper extraction below. Crafting and block-drop data are present. A Wrench cycles adjacent-transfer output faces through Auto, Input, Output, and Disabled. Horizon capability extraction remains all-side because the pinned energy hook has no block position. Configurable multipliers, flue gas, upgrades and custom screen behavior remain absent.
- **Firebox/Thermoelectric Plant:** the Firebox burns all five upstream fuels and makes 80 HU/t into a 40,000 HU store capped at 1,100°C. Charcoal has the shared 50% Wood Ash chance; ash is saved in an output slot and hopper-extractable below. While producing, its heat transfers at up to 100 HU/t at the full 1,100°C source temperature, matching Arcforge's source-temperature behavior; adjacent thermal conduits can carry this heat onward. The Thermoelectric Plant stores 20,000 HU/1,400°C and converts at the source curve: zero at 100°C, 1 FE/HU at 1,100°C, and up to 1.15 FE/HU at 1,400°C. It processes up to 102 HU/t into a 50,000 FE buffer and outputs at up to 200 FE/t. A Wrench cycles its adjacent-transfer output faces through Auto, Input, Output, and Disabled. Capability extraction remains all-side; upgrades and custom screens remain absent.
- **Firebox Array:** registers the source controller, casing, and Pressure Glass blocks and their three source-shaped crafting recipes. The controller validates a hollow 3–7 block box, with casing edges, casing or Pressure Glass walls, one outward-facing controller, and air inside. Its single input slot burns the existing Firebox solid fuels plus Coal Coke and Coal Coke blocks. Heat generation scales from 3,967 HU/t at 3×3×3 to 50,400 HU/t at 7×7×7; the HU buffer scales at 10,000 HU per volume block, with a 1,400°C maximum. Solid fuel pauses at its burn temperature; Coal Coke burns at 1,300°C and yields 1.5× coal heat. The controller rechecks formation every 40 ticks, saves bounds and heat state, and clears formed casing/glass when the shell breaks. Heat pushes to supported adjacent consumers at the array's scaled throughput. Liquid fuels, oxygen, flue gas, heat/input ports, upgrades, and the dedicated screen are not implemented.
- **Solar Thermal Array:** registers the source controller, casing, collector block, receiver tube, and trough mirror. Its 2×2×4 tower has four collector positions and is checked every 40 ticks; it stores up to 16,000 HU and models the 24,000-tick sun curve, clear/rain/thunder output modifiers, north/south versus east/west alignment, and collectors with full sky light above them. Generation is limited to `minecraft:overworld` because the pinned hooks do not expose a general has-sky query. The Wrench toggles saved heat-output faces on formed tower parts; enabled faces transfer heat to supported adjacent consumers or thermal conduits at a per-port rate of at least 100 HU/t and up to current production. Breaking a controller or structure part unforms the rest. Enabled output faces now render standard blockstate overlays using the upstream steel collar textures and heat-port plate texture; internal tower faces are hidden. The overlay approximates the source nozzle and does not calculate its depth from the multiblock model. Biome multipliers and snow-specific weather are unavailable through the pinned hooks; controls/status UI, a dedicated screen, and in-world verification remain unfinished.
- **Geothermal Plant:** the 8,000 mB native tank accepts only lava, from pipes, lava buckets, or its two-slot input. Vanilla bucket use requires room for the full 1,000 mB and stages the empty bucket before changing the tank; the input-only tank is updated atomically so rollback never depends on a drainable face. It burns 100 mB batches at 1 mB/t for 80 HU per mB into a 60,000 HU/1,400°C store; adjacent lava source blocks add 40 HU/t and magma blocks add 16 HU/t, rescanned every 20 ticks. Heat flows to supported adjacent consumers or thermal conduits at up to 100 HU per call, including through thermal conduits to the Thermoelectric Plant. The source-shaped recipe, block registration, and loot table are included. Upgrades, redstone control, side configuration, and a dedicated screen remain absent; the supported-neighbor transfer is an alpha simplification.
- **Fuel Burner/Fluid Tanks:** the four tank tiers store 16,000 / 64,000 / 256,000 / 1,024,000 mB through Horizon's native fluid capability. Full water/lava buckets retain vanilla all-or-nothing exchange; Arcforge Creosote/Latex buckets and all four portable canister tiers support partial hand exchange. Canister capacities/rates are 16,000/1,000 through 1,024,000/64,000 mB. Transfer rejects incompatible fluids, preserves unrelated custom data, and rolls back tank changes if inventory exchange fails. Horizon's generic item-fluid helpers only recognize vanilla water/lava, so custom-fluid transfer remains in our mod hook. Four source-shaped canister recipes provide survival access, but canisters transfer by hand rather than through Arcforge's automated tank slots. Tank and canister tier-upgrade recipes do not preserve stored fluid: the pinned crafting-result hook receives no ingredient stacks, preventing safe component copying. The fluid hook also has no per-tick rate field. Fuel Burner has an 8,000 mB input tank and a 40,000 HU/1,400°C store; it burns the currently registered Creosote at the source values of 120 HU/mB, 0.5 mB/t, and 850°C, preserving fractional fuel between ticks. Its heat transfers at up to 100 HU/t to supported adjacent consumers. Two-slot bucket automation consumes a full Creosote Bucket and returns an empty bucket. Other fuel data-map entries cannot be read by the pinned API and their fluid registrations/recipe paths are not implemented; oxygen, flue gas, side modes, upgrades, status controls, and custom screens remain absent.
- **Fluid Conduits:** Wrought, Tempered, Hardened, and Arcforged tiers transfer one fluid type through connected runs using Horizon's transactional `move_fluids` helper. Rates are 200 / 800 / 3,200 / 12,800 mB/t, limited by the slowest connected tier. Wrench faces default to Auto and use Horizon's sided `fluid_tanks` capability to detect drainable sources and fillable destinations; Input, Output, and Disabled remain manual options. The active fluid is held in the network routing cache until its accessible sources run dry, preserving the source's one-fluid-at-a-time rule without a conduit buffer. Sided endpoint discovery and topology caching are implemented, but the transfer path is not loaded or behavior-tested in-world. Conduit-held fluid storage, filters, gas handling, and animated fill rendering remain absent.
- **Thermal Conduits:** all four source tiers are registered at 50, 200, 800, and 51,200 HU/t. The mod discovers connected groups, pools HU across bidirectionally connected members, uses the lowest member tier as the pool rate, and scales storage by member count. Source input and consumer output each use a shared tier-rate budget per tick. One-way Output-to-Input links transfer through the destination pool, preserving direction and applying each pool's budget. HU and hottest carried source temperature are saved across member block entities. The scheduler uses the current block entity passed to Horizon's tick hook because that entity is absent from ordinary world lookups during its tick. Firebox, Firebox Array, Geothermal, Fuel Burner, and Solar can feed the networks, which push into supported Fiberizer, Vulcanizer, Grain Dryer, and Thermoelectric consumers. The Wrench configures each face through Auto/Input/Output/Disabled. Source-shaped recipes preserve tier ingredients, patterns, and output counts; base-tier tags and block drops are included. Horizon has no heat capability hook, so transport runs in mod-side ticks. Color data/dyed variants, component-preserving upgrades, and in-world behavior remain incomplete or unverified.
- **Energy Conduits and Wrench:** Wrought, Tempered, Hardened, and Arcforged tiers provide source rates of 256, 1,024, 8,192, and 262,144 FE/t. Bidirectionally connected members share the lowest tier's rate and a member-scaled pool; one-way Output-to-Input links transfer between separate pools. Mod-side producer input and network output each have a shared per-network rate budget, and pools distribute FE to supported Arcforge machines within their insertion limits and capacities. The scheduler uses the current block entity passed to Horizon's tick hook because that entity is absent from ordinary world lookups during its tick. Horizon's native energy capability remains per block and all-sided, so external calls bypass conduit face modes and the shared rate; the mod reconciles those changes before pooled writes, though direct calls may temporarily raise capacity. Previously saved FE from the old 50,000 FE per-block buffers is preserved; excess charge drains and the pool capacity returns to its normal member-rate limit. The Wrench cycles each face independently between Auto, Input, Output, and Disabled, including when the neighboring block is another conduit; the visible connection and pool topology respect configured direction. It also configures energy output faces on the Combustion and Thermoelectric Plants and rotates horizontal facing clockwise on supported single-block machines; multiblock controllers and the Resin Tap are excluded. Rotation currently changes facing state only; sided inventory/energy behavior remains all-side. The Wrought recipe, Wrench recipe, and all four conduit loot tables are source-identical. Three tier-upgrade recipes retain source patterns and counts in vanilla shaped form; custom component copying is omitted. Stored or recently transferred FE sets the imported active glow across the network; it compiles but remains unverified in-world. Wrench reverse-cycle and other modes, color/facade behavior, and animated flow remain outstanding.
- **Steel and alloy progression:** the Arcforge Furnace currently processes the source steel, Wrought, Tempered, Hardened, Arcforged alloy, and Graphite recipes with their upstream ingredient counts, heat gates, durations, coke costs, and slag outputs. The Arcite/Tungsten Composite crafting recipe was added byte-identical to the pinned source. The Arcforged Alloy recipe graph still depends on Carbon Fiber from Pitch, whose upstream Refinery source is not implemented, so end-tier alloy is not currently survival-obtainable through the port.
- **Steel tools and armor:** the five basic tools, Steel Hammer, Steel Excavator, and four armor pieces are registered with Arcforge models and source stats. Basic tools have 500 uses and 7.0 mining speed; Hammer and Excavator have 1,500 uses and 4.9 mining speed; armor has 25-material durability multipliers, 2/7/5/2 defense, and 1.0 toughness. All eleven use enchantability 12 and Steel Ingots for repairs. The eleven upstream crafting recipes are included. The Hammer/Excavator 3×3 break effect remains deferred: the pinned hooks cannot inspect arbitrary block hardness or block-entity presence, nor apply extra held-item durability per additional block. Foundry/flight equipment also remains unimplemented.
- **Energy Cells:** Wrought, Tempered, Hardened, and Arcforged tiers use source capacities of 500,000 / 4,000,000 / 32,000,000 / 256,000,000 FE and transfer rates of 512 / 2,048 / 16,384 / 262,144 FE/t. Their block-item forms declare Horizon native item-energy buffers at the matching capacities and rates. Player mining moves stored FE into the dropped block item; placing the charged item restores it to the new block entity while preserving custom item data. Per-tick charge snapshots supply the loot hook when a removal path does not expose the block entity; explosion behavior still needs in-world verification. Tier upgrades do not preserve charge. All six faces accept and extract energy because the static Horizon energy hook cannot determine the cell’s facing. The screen, item charging slots, redstone/comparator behavior, and charge-level rendering are not implemented.
- **Fiberizer/Vulcanizer/Grain Dryer:** the Fiberizer now has its source-shaped crafting recipe and all three upstream recipes, 20,000 FE capacity, and the 800°C/1,000°C minimums. The Vulcanizer uses the upstream 8,000 HU capacity, 400°C maximum, 140°C minimum, 200-tick batch, and 12 HU/t rate; it cures two raw or synthetic rubber with one sulfur dust into two Rubber. Its craft and machine recipes are included. The Grain Dryer uses the upstream 4,000 HU capacity, 250°C maximum, 60°C minimum, and 4 HU/t: the three 200-tick item recipes dry wheat, Hop Cones, and Sorghum Stalks; 250 mB Latex makes Raw Rubber over 300 ticks. Latex enters through its saved 4,000 mB input tank, and Firebox heat moves to the dryer through direct adjacency. The Grain Dryer has its upstream-shaped craft and block loot. Heat ports/conduits, upgrades, custom screens, and bucket interaction are absent.
- **Arcforge Furnace/Steelworks:** the Arcforge Furnace port validates the source 3×3×6 brick, wall, and port pattern in all four horizontal facings, requiring an open center and the port to face outward. It rechecks formation every 20 ticks and pauses processing when the structure is incomplete. Its six-slot inventory follows Arcforge’s metal/additives/coke/output/byproduct layout. Coke serves as both fuel and reagent, coke blocks yield nine loose coke, and each coke burns for 800 ticks while raising temperature by 2°C/tick to 1,600°C and cooling by 1°C/tick to ambient. The port runs all 12 upstream Arcforge smelting recipes, temperature gates, outputs, and slag byproducts. Furnace bricks, walls, port, and coke block have upstream loot; the bricks, walls, and port can be crafted, and coke blocks can be packed/unpacked with the upstream recipes. The standalone Steelworks prototype remains separate.
- **Induction Furnace:** 32 Arcforge ore/raw/dust smelting recipes load from a mod-side catalog. The source crafting path now includes the tungsten heating coil, copper rod tag, and furnace recipe. The furnace also retains a common vanilla fallback, runs at the source 20 FE/t with a 20,000 FE buffer, and uses half each recipe's cooking time (100 ticks for the standard 200-tick recipe). The pinned hook cannot query the vanilla recipe manager, so arbitrary vanilla/datapack recipes and the source Liquid Experience bank are not implemented.
- **Shared stores:** bounded integer energy and heat stores with rate limits and hot-to-cold heat transfer.

## Survival and assets

Twenty-five early crafting recipes provide paths to the Wrench, Carbonizer, Steelworks, Combustion Plant, Metal Press and dies, Sifter and meshes, steel block, Arc Crusher, furnace bricks, Firebox, Wrought Fluid Tank, Fuel Burner, Resin Tap, Grain Dryer, and Vulcanizer; two Pine Resin and kelp craft a slime ball. ## Runtime checkpoint and remaining proof

A disposable Horizon native build and imported-client smoke now confirm that the matching `native-mods.json` plus `.hmod` load Arcforge content, register custom IDs, and accept `/give` for a Heat Cell and Steel Ingot. All 15 Arcforge ore features were converted to this Horizon revision's supported flattened `worldgen/feature/` shape; startup no longer logs missing feature fields, block identifiers, or skipped Arcforge placements. This only verifies feature parsing, not actual ore frequency.

Machine processing, crafting progression, Heat Cell transfer and save/reload, item/fluid/energy networks, hopper compatibility, and multiplayer parity remain unverified. Conduit and Solar multipart blockstate definitions still produce unsupported-property warnings and their visuals need repair. The GitHub artifact workflow now needs a fresh run to publish the manifest and corrected source/data changes.
